Entry form without layout shift

Three directions for the one form shared by Add and Edit. All three drop the bottom sheet that grows and slides with the keyboard. Frames are 390×844 scaled to 76%. The names and amounts are examples.

Why the form shifts today
  • The sheet sits on the bottom edge, which is exactly where the iOS keyboard lands, so iOS pans the page to keep the focused field visible.
  • Amount, Notes and every "+ New…" field raise the keyboard. Each tap on Type, Account, Category, Merchant or Date dismisses it again, because native selects and the date picker take focus.
  • The decimal pad and the text keyboard are different heights, so Amount → Notes moves things a second time.

  • How: a full-screen page sized to visualViewport.height. Chips call preventDefault on pointerdown, so the amount field never loses focus.
  • Native selects and the date picker have to go. Each one closes the keyboard when tapped. They become chip rows plus a ‹ Today › stepper for the date.

  • Even if the layout is perfect, the keyboard height still changes between Amount and Notes.
